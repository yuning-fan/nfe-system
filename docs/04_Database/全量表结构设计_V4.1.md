# NFE 系统全量数据库设计 V4.1 — 终稿 (Supabase / PostgreSQL)

本版为提交开发的**最终定稿版**。共包含 **37 张业务表 + 1 张视图**，全面覆盖了业务方案书中的所有功能模块。

> **V4→V4.1 核心变更**：新增「项目与选课体系」6 张表（program_types → programs → program_subjects → student_enrollments → student_subject_selections → school_timetable），建立奥大课程体系与机构辅导体系的双轨并行结构。

### 视图 `v_student_current_enrollment` (当前报名)
一名学生可有多条报名（如已预缴奥大项目 → 预科 + 奥大两条）。总览每人一行，需取「当前」那条。

**优先级**（顺序不可调换）：
1. `status = 'active'` 优先（`completed`/`withdrawn` 不算当前）——**关键**，两条 enrollment 日期全空时仅靠日期无法判定
2. 今天落在 `[start_date, end_date]` 内
3. 都未开始 → 取最早开始（绿通 9 月那批 = 预科，而非已预缴的奥大）
4. 都已结束 → 取最晚结束

输出：`student_id / enrollment_id / program_id / program_name / program_stage(UOA|UP) / source / status / start_date / end_date / enrollment_count`

### 视图 `v_student_overview` (在读学生总览)
面向管理层的导出用视图，中文列名，对齐线下《动态表格_nfe.xlsx》。仅含 `profiles.status = 1` 的在读学生。

- **市场来源**：入库存明细，视图归类为名校/绿通。规则「X转Y 取 Y」（名校转绿通→绿通、绿通转名校→名校）；`market_source` 为空时按 `enrollment.source` 兜底推导，并用 `市场来源为推导值` 列标记。
- **住宿三列**（居住类型/学生公寓/公寓编号）暂未纳入，待排房定稿。
- 两视图均 `security_invoker = true`，以便后续 RLS 生效（不设则视图会绕过 RLS）。

> ⚠️ 修改这两个视图的列名或列序时必须 `drop view` + `create view`；
> `create or replace view` 不允许改列名（ERROR 42P16）。

### `v_course_remaining` (课时余额实时视图)
```sql
CREATE VIEW v_course_remaining AS
SELECT
  ca.id,
  ca.student_id,
  ca.course_id,
  ca.total_hours,
  ca.total_hours + COALESCE(SUM(lhc.change_amount), 0) AS remaining_hours
FROM course_assets ca
LEFT JOIN log_hour_changes lhc
  ON lhc.student_id = ca.student_id
  AND lhc.course_id = ca.course_id
GROUP BY ca.id, ca.student_id, ca.course_id, ca.total_hours;
```
