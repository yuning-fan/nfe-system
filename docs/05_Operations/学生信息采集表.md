# 学生信息采集表 —— 需要收集的数据清单

> 本文档用于指导线下收集在读学生信息，按照数据库表结构整理。  
> **黑体**字段为必填项，其余为选填/系统自动生成。

---

## 📌 第一层：账号与基础身份（核心，必须）

### 表 `profiles` — 系统账号

| 字段 | 类型 | 说明 |
|---|---|---|
| **full_name** | 文字 | 学生中文姓名 |
| phone | 文字 | 手机号（新西兰或中国号） |
| avatar_url | 图片URL | 头像（可后期上传） |

---

## 📌 第二层：学生档案（每人必填）

### 表 `students_info` — 学生详细档案

| 字段 | 类型 | 说明 |
|---|---|---|
| **english_name** | 文字 | 英文姓名（如 Michael Zhang） |
| **gender** | 选项 | 性别：male（男）/ female（女） |
| **date_of_birth** | 日期 | 出生日期（YYYY-MM-DD） |
| **passport_number** | 文字 | 护照号码 |
| **school_name** | 文字 | 目前就读学校（如 Avondale College / MAGS） |
| source_school | 文字 | 国内原来就读的学校 |
| english_level | 文字 | 英语水平（如 IELTS 6.0 / 新手） |
| target_university | 文字 | 目标大学（如 University of Auckland） |
| scholarship_requirement | 文字 | 奖学金要求/目标 |
| **emergency_contact_name** | 文字 | 紧急联系人姓名（家长） |
| **emergency_contact_phone** | 文字 | 紧急联系人电话 |
| emergency_contact_email | 文字 | 紧急联系人邮箱（家长邮箱） |
| home_address | 文字 | **国内**家庭住址（新西兰住址由宿舍分配自动带出，不在此填） |
| arrival_date | 日期 | 抵达新西兰日期 |
| payment_note | 文字 | 缴费/财务备注 |
| health_notes | 文字 | 健康/过敏/用药备注（重要！） |

---

## 📌 第三层：项目与阶段（入学必填）

### 表 `student_enrollments` — 入学信息

| 字段 | 类型 | 说明 |
|---|---|---|
| **source** | 选项 | 商务来源：绿通 (Green Channel) / 散客 (Agent) |
| **program_id** | 选项 | 当前学习阶段（见下方列表） |
| cohort_name | 文字 | 入学批次（如 2026-S1） |
| **start_date** | 日期 | 入学日期 |
| **end_date** | 日期 | 预计结束日期 |

> **可用学习阶段列表**：
> 1: 预科-Standard (12月)
> 2: 预科-Accelerated (5月)
> 3: 预科-Fast-track (8月)
> 4: 大学阶段-住宿监管

### 表 `student_documents` — 签证/保险/护照文件

| 字段 | 类型 | 说明 |
|---|---|---|
| **doc_type** | 选项 | 文件类型：`offer_letter`(录取通知书) / `visa`(签证) / `insurance`(保险) / `guardianship`(监护协议) / `passport`(护照) |
| file_url | 文件URL | 文件存储地址（上线后接 R2） |
| issue_date | 日期 | 签发日期 |
| **expiry_date** | 日期 | **到期日期（签证到期最重要！）** |

> ⚠️ **入学清单功能依赖这些文件类型**：系统的「入学清单检测」（详情页卡片 + 列表"X项待补"角标）会逐项检查 `offer_letter`、`visa`、`insurance`、`guardianship` 是否齐全。采集时务必按上面的英文值录入，否则清单会一直显示缺失。

## 📌 第七层：项目选课与学校课表（预科/大学项目学生必填）

| 字段 | 类型 | 说明 |
|---|---|---|

> **提示**：如果有学校发放的官方 PDF 课表，可直接上传，由学管代为录入系统。

## ✅ 建议收集顺序

**每个学生需要收集的最小数据集（按优先级）：**

1. **中文姓名 + 英文姓名** → 建账号
2. **出生日期 + 护照号** → 档案
3. **就读学校** → 接送/课表
4. **签证到期日** → 证件预警（最重要！）
5. **紧急联系人（家长）姓名 + 电话 + 邮箱** → 安全合规与家校沟通
6. **入学日期 + 项目类型** → 录入 enrollment
7. **已选学校科目（选修/必修）** → 建立 subject_selections
8. **学校每周官方课表（周一至周五）** → 录入 school_timetable，用于排课避让
9. **抵达日期 + 家庭住址** → 线下安顿与接送安排
10. **已购课时数**（有辅导课的学生）→ 初始化课时账本
11. **宿舍房间**（住宿生）→ 初始化住宿安排
12. **缴费备注/健康备注**（如有）→ 完善档案

## 🧪 测试数据建议（为跑通系统各项功能）

> 真实采集时按实际填；如果是**造测试数据**，建议刻意制造差异，让各类告警/状态都能被触发到，从而验证功能。

| 要测的功能 | 怎么造数据 |
|---|---|
| 首页**红色预警横幅** | 让 1~2 个学生的签证 `expiry_date` 设在 **14 天内** |
| 首页**签证黄色预警** | 让几个学生签证到期日设在 **90 天内** |
| **课时余额红色预警** | 给某学生 `course_assets.total_hours` 设成 **≤5** |
| **入学清单"X项待补"** | 留 1~2 个学生**故意缺**几项（如不传 guardianship / 不填 arrival_date / 不分宿舍） |
| **入学清单全绿** | 至少 1 个学生把 7 项（offer/visa/insurance/guardianship/抵达日/宿舍/选课）**全部补齐** |
| **接送名单** | 让 2~3 个学生进**同一条 route**，验证接送页按路线聚合 |
| **风险等级分布** | 让学生 `risk_level` 覆盖 green / yellow / red 三档 |
| **学校平台账户卡片** | 给 1 个学生填 `student_credentials`，验证明文/密文切换与权限 |
| **生日提醒** | 把某学生 `date_of_birth` 的月/日设成**今天**，验证首页今日生日 |
