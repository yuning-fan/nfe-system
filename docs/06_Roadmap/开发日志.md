## 2026-06-17 · Phase 5 · 核心业务模型重构 (Programs & Source)

### 📋 概述

本次变更旨在解决系统初期设计中将“商业来源（商务归属）”和“学习阶段（系统功能模块）”混为一谈的问题。现将二者解耦，确保逻辑准确，并为即将到来的大规模学生数据导入打好地基。

---

### 🏗️ 架构与数据库重构

#### 核心痛点与解决思路
**问题**：旧的 `programs` 表中存在如“绿通-Standard”、“名校散客”、“绿通转名校”等选项。这导致了逻辑混淆：“绿通”是一个商务来源概念（全包VIP），而“Standard (12月)”是一个学制概念。
**方案**：将业务拆分为两个独立维度：
1. **商务来源 (`source`)**：转移至 `student_enrollments` 表中。
2. **学习阶段 (`program_id`)**：净化 `programs` 表，使其仅表示纯粹的学制与阶段。

#### 具体的 DDL 变更
- 新增枚举 `enrollment_source`，包含 `green_channel` (绿通) 和 `agent` (散客)。
- `student_enrollments` 表新增 `source` 字段。
- `program_track` 枚举新增 `fast_track` 和 `university`。
- 重构 `programs` 表字典项，使其变为：
  - `预科-Standard (12月)`
  - `预科-Accelerated (5月)`
  - `预科-Fast-track (8月)`
  - `大学阶段-住宿监管`
- 清除了多余的历史废弃 Program 项。

#### 历史数据平滑迁移
- 针对 `student_enrollments` 中已存在的 37 条真实数据，编写了迁移脚本。
- 根据旧的 `program_id` 自动提取其商务属性更新至新加的 `source` 字段，并将他们安全地挂载到合并后的正确预科阶段上，做到了无损迁移。

---

### 🖥️ 前端页面与文档变更

#### 页面变更
- `src/pages/Students/StudentList.tsx`：在表格的“项目”列中，加入了“绿通”与“散客”的 Badge（Pill）动态渲染。
- `src/pages/Students/StudentDetail.tsx`：详情页顶部 Tag 及资料卡片新增 `source` 来源显示逻辑。

### 📐 技术决策备注

#### 关于 `supabase as any` 模式

项目中 `@supabase/supabase-js` 的类型推断依赖于本地生成的 `database.types.ts`。由于当前项目**未运行 `supabase gen types typescript`** 生成类型文件，所有自定义表（`warning_letters`、`reports`、`students_info` 等）的 insert/update 参数都会被推断为 `never`。

**当前采用的临时方案**: 在每个 store 文件中声明 `const db = supabase as any`，将 Supabase 调用链的类型推断完全绕过。

**上线前应改为正确方案**: 运行 `npx supabase gen types typescript --local > src/types/database.types.ts`，生成完整的类型定义文件，让 Supabase client 获得正确的表级类型推断。
