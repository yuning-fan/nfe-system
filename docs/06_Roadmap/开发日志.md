## 2026-06-18 · Phase 7 · 文件上传体系（Cloudflare R2）

### 📋 概述

接入完整的文件上传/下载能力，存储采用 Cloudflare R2，通过 Supabase Edge Function 签发预签名 URL（R2 Secret 永不下发前端）。覆盖证件、头像、课件、报告 PDF、资料库共 5 类文件场景。

### ☁️ 存储与签名架构

```
前端 → Edge Function r2-sign（持R2 Secret，校验登录态+角色）→ 返回预签名URL
     → 浏览器直传/直读 R2（PUT/GET）→ 文件路径(key)存入数据库
```

- **R2 桶**（区域 APAC）：`student-docs`(敏感) / `materials` / `reports` / `avatars` / `resources`，全部私有，统一走预签名访问。
- **Edge Function `r2-sign`**（`supabase/functions/r2-sign/index.ts`）：用 `aws4fetch` 生成 SigV4 预签名 URL；桶名白名单校验；敏感桶 `student-docs` 仅 `admin`/`manager` 可签发；上传URL有效 5 分钟、下载 10 分钟。
- R2 三凭证（Account ID / Access Key / Secret）以 `supabase secrets` 形式存于云端，不入仓库、不入前端。
- 已端到端验证：①签发上传URL→②PUT→③下载读回；角色拦截（life→敏感桶 403、未登录 401）均通过。

### 📐 技术决策备注

#### 关于 `supabase as any` 模式

项目中 `@supabase/supabase-js` 的类型推断依赖于本地生成的 `database.types.ts`。由于当前项目**未运行 `supabase gen types typescript`** 生成类型文件，所有自定义表（`warning_letters`、`reports`、`students_info` 等）的 insert/update 参数都会被推断为 `never`。

**当前采用的临时方案**: 在每个 store 文件中声明 `const db = supabase as any`，将 Supabase 调用链的类型推断完全绕过。

**上线前应改为正确方案**: 运行 `npx supabase gen types typescript --local > src/types/database.types.ts`，生成完整的类型定义文件，让 Supabase client 获得正确的表级类型推断。
