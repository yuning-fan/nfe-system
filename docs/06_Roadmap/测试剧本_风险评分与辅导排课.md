# 测试剧本 · 风险评分 + 辅导排课（端到端）

> 用途：手动跑一遍验证近期所有改动。每步带「操作」「预期」「重点检查」。
> 角色切换：员工工作台直接改地址即可（无需多账号）——`/staff/patrol`（巡查）、`/staff/life`（生活）、`/staff/tutor`（辅导）、`/staff/academic`（学管）。

## 0. 前置（务必先做）
1. 两个迁移已推到云端 DB：`check_type` 加 `tutoring`、`schedule_status` 加 `absent/leave/cancelled`。
2. 系统里已有几名在读学生（profiles.role=student）。
3. 进 **风险预警** 页 → 点「一键重算全员风险分」→ 预期：不报错；没有任何违规/缺勤的学生应为绿、100 分。

> ⚠️ 关键约定：测试「辅导销课」时，排课的**辅导老师要选你当前登录的账号**（上课记录按登录人 = tutor_id 过滤），否则你在「上课记录」里看不到那节课。

## 1. 学管 · 建课程
- **操作**：`/staff/academic` → 课程管理 → 「导入预设科目」。
- **预期**：出现 14 门「班科」(英语EAP + 13 选修)。
- **再操作**：新建一门「物理（1对1）」，课型选 1对1。
- **重点检查**：列表能新建/编辑/删除；重复点导入不会重复建。

## 2. 学管 · 充课时 + 排课
- **操作 A**：学业跟进 → 课时管理 → 给「学生甲」的「物理（1对1）」充值 10 小时。
- **操作 B**：学业跟进 → 辅导排课 → 「新建排课申请」：学生甲、辅导老师=**你自己的账号**、课程=物理（1对1）、时间=**今天**、时长 1 小时 → 提交。
- **预期**：进入「待审批」。
- **操作 C**：待审批 → 通过。
- **重点检查**：通过后回课时管理，**课时仍是 10 小时未扣**（新规则：审批不扣，销课才扣）。

## 3. 辅导 · 销课（验证扣课时 + 缺勤扣风险）
- **操作**：`/staff/tutor` → 上课记录 → 「待销课」应看到第 2 步那节课。
- **3a 出席**：点「销课」→ 选「出席」→ 填公开反馈 → 提交。
  - **预期**：课进入「已上课记录」=已完成；回课时管理，课时 **10 → 9**。
- **3b 缺勤**：再按第 2 步建一节今天的课并审批，回上课记录销课 → 选「无故缺勤」→ 提交。
  - **预期**：课时再扣 1；**学生甲风险分自动下降 −8**，回风险预警页能看到甲变黄/进列表 + 一条「自动算分」变更记录。
- **3c 请假**：再建一节销课选「请假」。
  - **预期**：**课时不扣、风险分不扣**。
- **重点检查**：未到时间的课（把时间设成明天）「销课」应点不动（限今天及以前）。

## 4. 辅导 · 调课闭环
- **操作**：上课记录某节待销课 → 「申请调课」→ 选新时间 + 原因 → 提交。
- **预期**：该课变「调课中」。
- **操作**：`/staff/academic` → 辅导排课 → 「调课审批」tab → 通过。
- **预期**：课表时间更新为新时间，状态回「待上课」。

## 5. 巡查 · 晚自习点名
- **操作**：`/staff/patrol` → 晚自习点名 → 默认全员在场 → 把「学生乙」标缺席 → 提交点名。
- **预期**：提示缺席 1 人；**乙风险分 −8**，风险页可见。
- **改错验证**：历史点名记录 → 展开今天 → 把乙改回「在场」→ 预期乙风险分回升；或「删当天」→ 同样回升。

## 6. 生活 · 早上出勤
- **操作**：`/staff/life` → 早上出勤确认。
- **预期**：列出「今日有课」的学生（依赖 `school_timetable`）。
  - 若显示「今日无排课学生」= 课表没数据，属正常，可跳过或先补课表。
- **操作**：标某生「缺席」→ 提交 → 预期该生 −8。

## 7. 违规 + 三步走警告信
- **操作 A**：`/staff/academic`（或巡查）→ 违规记录 → 新增违规：学生丙、缺席自习(−8)、填说明 → 保存。
  - **预期**：提示「风险分已更新为 XX」，丙被扣分。
- **操作 B**：该违规行 → 「申请警告信」→ 选级别+佐证 → 提交。
- **操作 C**：风险预警页 → 「待审批警告信」→ 批准下发。
  - **预期**：警告信记入累计，丙风险分按「警告信累计」口径再调整（第1封 −10…）。

## 8. 看板总检查（学管/admin 风险预警页）
- 红/黄/绿统计数与上面操作一致；
- 「近期等级变更记录」有 system_auto（自动算分）和 manual_override（审批）两类；
- 「一键重算全员」再点一次，结果应稳定不乱跳。
