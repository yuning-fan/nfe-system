# 警告信与预警体系 · 设计（待审）

> 创建：2026-06-26　状态：设计稿，待确认后开发
> 目标：平衡「学校警告信（外部红线）」与「NFE 内部警告信（预防）」，让内部体系**防微杜渐**——在学校发信/劝退之前先介入。

## 一、两条线的定位

| | 学校线（外部） | NFE 内部线 |
|---|---|---|
| 谁发 | 学校，NFE 不可控 | NFE 自己，可控 |
| 触发 | 出勤率 < 93%、学术不端（作弊等） | 风险分、出勤率逼近、违纪苗头 |
| 后果 | 累计 **3 封 → 劝退** | 提醒 / 家长沟通 / 三步走 |
| 定位 | 结果（红线，已破皮） | 过程（预防） |
| 系统角色 | **记录 + 上传 + 红线预警** | **主动干预** |

核心原则：**内部触发线前置于学校线**，给自己留缓冲。

## 二、出勤率（双轨 + 双红线，据合约修正）

> 合约依据（绿通第二/四条、名校第二条）：**NFE 自己的硬线是出勤率 ≥ 95%**，比学校 93% 还严。低于 95% 即构成违约，但 **NFE 实操是先劝说、屡教不改才升级**（见第三、九节），不是自动取消资格。

1. **官方出勤率**（红线依据）：学管/生活从学校账户**手动录入**到学生档案，字段 `school_attendance_rate`（%）+ 更新日期。
2. **内部估算出勤率**（日常苗头）：生活老师早上出勤（`daily_checks` morning）滚动计算，不等于官方数字，仅作内部预警与扣分。
3. **两条红线 + 前置预警**（95% > 93%，NFE 合约线先亮）：
   - 内部预警：**≤ 97% 黄**、**≤ 96% 橙**（逼近合约线）
   - **< 95% = 违反 NFE 合约** → 触发**内部劝说**（不是自动取消资格）+ 风险红
   - **< 93% = 学校红线** → 学校发警告信
   - 官方录入值作红线判断，内部估算作日常提醒。

## 三、预警升级阶梯（防微杜渐骨架）

```
苗头   单次缺勤/违纪              → 扣风险分、记录，无信件
 ↓
L1内部 风险分转黄 / 出勤率≤97%     → 内部口头提醒 + 家长沟通（报告里标黄）
 ↓
L2内部 出勤率<95%（违反合约线）    → NFE 内部「劝说」一次 + 记录；回升后再跌→再劝说，累计"屡教不改"次数
 ↓
L3内部 屡教不改                   → NFE 三步走电子警告信（内部正式）
 ↓
L3外部 出勤率<93% / 作弊          → 学校警告信（NFE 登记+上传，外部红线）
 ↓
L4劝退 屡教不改 ＋ 学校也发警告信   → 人工综合评估 → 走劝退（取消资格·不退费，合约第四条）
```
关键：**劝退是人工综合判断，需"内部屡教不改"与"学校警告信"两个条件叠加**，系统只负责攒证据+给信号（见第九节）。L1/L2 要早早自动亮起。

## 四、信件体系分工

- **报告类**（2026-06-26 定）= 常规沟通，分两种：
  - **出勤报告**：**两周一发**。
  - **学术报告**：**一月一发**。
  - 两者都内嵌「预警提示区」：指标接近阈值自动标黄。家长在收到任何警告信之前就看到苗头 = 防微杜渐。
- **警告类**（内部三步走 / 学校警告）= 处分性质，分级留痕走流程。
  - 内部三步走：NFE 自己的 L2。
  - 学校警告：外部 L3，NFE 只登记+上传。

## 五、数据模型改动

### 1. `warning_letters` 加字段
- `source`：`internal`(内部三步走) / `school`(学校信)
- `category`：`attendance`(出勤) / `academic`(学术·作弊) / `discipline`(纪律)
- `attachment_url`：学校信扫描件/PDF（学管上传，走 R2）
- 现有内部三步走数据默认 `source=internal, category=discipline`。

### 2. 学生档案 / `students_info` 加
- `school_attendance_rate` numeric（官方出勤率 %）+ `attendance_rate_updated_at`
- 学校警告信计数与「距劝退还差几封」由 `warning_letters where source=school` 实时算。

### 3. 风险评分引擎
- 新增扣分/红线项：官方出勤率 < 93% → 触发（建议直接黄/红，硬约束）；学校警告信累计计入（第 3 封 → 劝退预警，硬触发红）。
- 内部估算出勤率 ≤ 96% → 提醒；≤ 94% → 红。

### 4. 「劝说」记录（屡教不改的依据）
- 新增劝说记录：`type=出勤/纪律/学术`、日期、原因、当时出勤率、劝说人、内容。可复用 `communication_logs` 或新表 `persuasion_logs`。
- 系统自动统计「出勤率反复跌破 95% 的次数」与「劝说次数」= 屡教不改强度。

### 5. 风险看板分两栏
- 左「内部预防」：风险分、内部三步走、扣分明细、**劝说次数 / 出勤反复次数**。
- 右「学校红线」：官方出勤率、学校警告信张数、最近一封附件。

### 6. 劝退评估面板（见第九节）
- 聚合「内部屡教不改」+「学校警告信」两个条件，给出是否达到劝退参考，但**最终人工决定**。

## 六、学校警告信录入（学管，已定：登记+上传）
- 学管在「学生档案 / 风险」处新增学校警告信：选 category（出勤/学术/纪律）+ 日期 + 原因 + **上传附件**（R2，复用 FileUploadButton）。
- 累计满 3 封 → 学生标「劝退流程」+ 看板置顶。

## 九、劝退评估（人工拍板，系统给信号）

合约的"劝退"= 取消学员资格 + 不退费（合约第四条），NFE 实操需**两个条件叠加**：
- **条件 A 内部屡教不改**：出勤率反复跌破 95%、多次劝说无效 / 三步走已到 L3。
- **条件 B 学校已发警告信**：`warning_letters where source=school` ≥ 1（或按学校劝退进度）。

系统做的：
1. 学生档案/风险页一个「劝退评估」卡片，同时显示 A、B 两组证据（劝说次数、出勤反复次数、内部三步走进度、学校警告信张数+附件）。
2. 两条件都满足 → 卡片提示「**已达劝退评估条件，请人工复核**」+ 看板置顶。**系统不自动劝退**。
3. 人工确认走劝退 → 记一条处置记录（取消资格，引用合约第四条），不退费标记。

> 单纯出勤率 < 95% **不**自动触发劝退，只触发"劝说"。

## 十、报告系统（二期·待开发）

### 报告种类与周期
- **出勤报告**：**两周一发**。内容：本期出勤率（官方+内部估算）、缺勤/迟到明细、与合约线 95% 的对比。

- 命中红线则醒目提示（出勤<95%、有学校/内部警告信）。
