# 警告信与三步走干预流 (Warning Letter Workflow)

## 1. 业务背景
为满足 DCG (未成年留学生照顾) 监管要求，机构必须对出现异常情况（如多次无故缺勤、违反住宿纪律等）的学生进行系统化的分级预警和干预，并留下完整的审计日志（Audit Trail）。

## 2. 角色与权限
- **发起人**：任何教职员工（Tutor / Admin / Manager）
- **审批人**：`admin` 或 `manager` 角色
- **受影响对象**：学生 (`students_info`)

## 3. 核心流程

### Step 1: 发现问题并触发警告
辅导员或管理员在「风险预警大盘」点击某个学生的【触发三步走警告】按钮。
此时需填写：
1. 警告级别 (1级 Verbal / 2级 Written / 3级 Final)
2. 具体违规事实与佐证（Evidence）

> **底层逻辑**：向 `warning_letters` 表插入一条记录，`status` 为 `pending_approval`。

### Step 2: 管理层审批
系统在上方会展示所有处于待审批状态的警告信队列。
拥有 `admin` 或 `manager` 权限的用户可以点击【批准下发】。

> **底层逻辑**：
> 1. 更新 `warning_letters.status` 为 `issued`
> 2. 根据不同级别自动计算风险扣分（1级不扣分，2级扣10分，3级扣20分），并更新至 `students_info.total_risk_score`
> 3. 更新 `students_info.risk_level`（升至 yellow 或 red）
> 4. 往 `log_risk_changes` 插入一条等级变更记录以备审计。

### Step 3: 后续跟进（待完善）
学生或家长签字确认后（目前为预留扩展点），警告信将更新为 `signed_onsite` 状态。

## 4. 相关数据表
- `warning_letters`: 存储警告信正文及状态流转
- `log_risk_changes`: 核心审计表，记录所有的风险等级变化
- `students_info`: 存储最终反映在界面的 `risk_level` 与 `total_risk_score` 字段。
