# 前端开发与架构规范

> **最后更新**: 2026-06
> **更新说明**: 根据第一阶段的实施结果，确立为 Vanilla CSS + Zustand + Supabase 架构。

## 1. 技术栈说明
- **框架**: React 19 + Vite 8
- **语言**: TypeScript (严格模式)
- **样式**: Vanilla CSS (`src/styles/` 集中管理) + CSS Modules (按需)。原则上避免引入过重 UI 组件库的样式，优先使用 CSS Variables 保证项目风格一致性和性能。
- **状态管理**: Zustand (`src/store/`)
- **路由**: React Router v7
- **图标**: Tabler Icons (`@tabler/icons-react`)
- **数据层**: `@supabase/supabase-js`

## 2. 目录结构规范
```text
nfe-admin-web/
├── src/
│   ├── assets/       # 静态资源 (图片/字体)
│   ├── components/   # 全局木偶组件 (UI组件、无状态)
│   ├── layouts/      # 布局组件 (Sidebar, Header等)
│   ├── lib/          # 第三方库初始化配置 (supabase.ts等)
│   ├── pages/        # 页面级组件 (按业务模块划分，如 Students, Academic)
│   ├── store/        # Zustand 全局状态
│   ├── styles/       # 全局样式配置与变量 (index.css)
│   └── types/        # 全局 TypeScript 接口声明 (database.ts)
```

## 3. 状态管理约定 (Zustand + Supabase)
1. **Store 的职责**：
   Zustand store (如 `useStudentStore.ts`) 必须承担**数据获取 (fetch)**、**状态缓存 (state)** 和 **错误处理 (error)** 的全部职责。
2. **UI 组件的职责**：
   React 组件 (如 `StudentList.tsx`) 仅负责调用 store 的 hooks，并根据 state 进行视图渲染，**严禁**在 UI 组件内部直接写 `supabase.from().select()` 逻辑。
3. **数据映射 (Mapping)**：
   数据库中采用的英文 Enums (如 `risk_level: green`) 必须在 UI 渲染时通过专门的 Mapping 函数转换为直观的中文标签（如 `🟢 正常`）。

## 4. UI 与 CSS 规范
- **禁止硬编码颜色**：必须使用 `index.css` 中定义的 CSS Variables (`var(--color-primary)` 等)。
- **审美底线要求**：避免原生浏览器组件感。运用玻璃态、细微渐变、合理的留白以及圆角(`var(--radius-md)`)来确保现代且专业（Premium）的质感。
- **交互规范**：按钮与链接需设置 `:hover` 伪类，提供平滑的过渡动画（如 `transition: all 0.2s ease`）。
