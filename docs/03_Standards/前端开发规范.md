# NFE 项目：前端开发规范

本规范适用于 `nfe-admin-web` 前端工程，主要技术栈为 **React 18 + TypeScript + Vite + Ant Design**。

## 1. 目录结构规范

```text
src/
├── assets/         # 静态资源 (图片、svg等)
├── components/     # 全局复用的 UI 组件 (如 Layout, 通用表格)
├── hooks/          # 自定义 React Hooks (如 useAuth, useTable)
├── pages/          # 路由页面，按业务模块划分 (如 Students, Courses, Schedules)
├── services/       # API 请求封装层 (调用 Supabase Client)
├── store/          # 全局状态管理 (如 Zustand 或 Context)
├── styles/         # 全局样式与变量 (Antd 主题覆盖)
├── types/          # 全局 TypeScript 类型定义 (如 Database 自动生成的 Type)
└── utils/          # 工具函数 (如 日期格式化、文件处理)
```

## 2. 命名约定

*   **文件与文件夹**：
    *   `pages/` 和 `components/` 下的文件使用 **PascalCase** (大驼峰)，例如 `StudentList.tsx`。
    *   其余目录 (`hooks/`, `utils/`, `services/`) 使用 **camelCase** (小驼峰)，例如 `useAuth.ts`, `formatDate.ts`。
*   **变量与函数**：使用 **camelCase**。
*   **常量**：使用 **UPPER_SNAKE_CASE** (大写下划线)，例如 `MAX_UPLOAD_SIZE = 1024`。
*   **类型与接口 (TypeScript)**：使用 **PascalCase**。

## 3. 组件编写规范

*   一律使用 **Function Component + Hooks**。
*   每个组件文件只包含一个默认导出的主组件。
*   避免组件过于庞大，单个文件超过 300 行时考虑拆分子组件。

## 4. 状态管理

*   **本地状态**：优先使用 `useState` 和 `useReducer`。
*   **跨组件状态**：对于全局用户状态 (`user`, `session`) 使用全局 Store。
*   **服务端状态**：API 获取的数据建议配合 React Query 或 SWR 进行缓存和重试管理，避免在 `useEffect` 中手动 fetch 后塞入 `useState` 造成代码冗长。

## 5. UI 与样式规范

*   **Ant Design**：绝大部分 UI 使用 Ant Design 标准组件，通过 ConfigProvider 统一调整主色调。
*   **CSS方案**：避免全局污染，优先使用 CSS Modules (`*.module.css` 或 `*.module.scss`)，或者直接在组件内使用内联样式进行微调。
*   **响应式**：后台管理系统主要适配 PC 端，最小宽度适配至 `1024px`。
